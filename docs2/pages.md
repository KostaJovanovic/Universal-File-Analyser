# Pages

Every top-level page on the site: its purpose, how it boots, and any special
wiring. All pages share one shell (`.site-header` / `.site-nav` / `.site-main` /
`.site-footer`), load `web/assets/js/core/app.js` as a module (which runs `boot()`)
and `navigate.js` for SPA transitions, and register the service worker. Clean URLs
are canonical (`/about`, `/compare`, …); the `.html` form 308-redirects.

`boot()` in `app.js` runs on first load and on every SPA `anr:navigate`. Its
per-page wiring guards on page-specific element IDs, so the same `boot()` is inert
on pages that lack them (the compare zones, the samples chips, the format CTA, the
stats page, etc. each only wake on their own page).

## The `/compare` page (special wiring)

`compare.html` carries two dropzones, `#cmpDropA` and `#cmpDropB`. `boot()` wires
them via `wireCompareZone()`: each captures one `File` **without** going through
`handleFile`, and the comparison runs **automatically** as soon as both files are
present (no button). The zones `stopPropagation` their own drops, and the page-wide
drop handler skips the compare page, so only the A/B zones accept files there. Runs
are serialised (`runCompare`/`maybeCompare`) so swapping a file mid-render re-runs
cleanly instead of interleaving.

`handleCompare()` counts both files toward the anonymous tally (one `recordAnalysed`
each), shows the shared loader, then calls `renderCompare()` from
`web/assets/js/renderers/compare.js`, passing `{ classify: resolveKind, routes:
ROUTES, ensureExifr, renderExtras: renderFileExtras }`. `renderCompare` runs each
file through the real `classifyFile()`/`ROUTES` renderer into an off-screen staging
container, then **moves** (not clones) the readout cells into merged `Field | A | B`
tables so tooltips and deferred async fills (e.g. the SHA-256 cell) keep working.
Rows whose values differ are tagged `.is-diff` (the "Show differences" toggle);
non-readout content falls back to a side-by-side A | B split. Media renderers are
invoked with `{ inline: true }` so they don't target the home page's fixed sections.
The compare page is a full main page (listed in `sw.js` `SHELL`, the sitemap, and
both stamp-head/stamp-footer `PAGES`). See `docs2/features/cross-cutting.md`.

## The `/atari` easter egg (special wiring)

`atari.html` hosts an Asteroids game where the asteroids are supported file formats.
It has a `#atariPlay` button; `app.js` loads the game modules (`assets/js/games/*`,
all listed in `sw.js` `SHELL`) to run it, and shows a dev-only debug control on dev
hosts. The page also carries the dependency-credits list (each vendored library with
its licence link) and a collapsible section toggle. Game internals are out of scope
for these docs beyond this mention.

## SPA navigation and the preserved home main

`navigate.js` swaps `.site-mark`/`.site-nav`/`.site-main`/`.site-footer` in place on
same-origin link clicks (View Transitions API), firing `anr:navigate` so `boot()`
re-runs. Two behaviours matter across pages:

- **Leaving home with a live analysis** (body has `anr-has-file`) stashes the whole
  `.site-main` node in `window._anrHomeMain` instead of discarding it. Media is
  paused first (a detached `<audio>`/`<video>` keeps playing; Web Audio players are
  stopped via `window._anrMediaStoppers`).
- **Returning home** reuses the stashed main verbatim - DOM, listeners, media
  position, resolved async cells - and sets `window._anrHomeRestored` so `boot()`
  skips re-wiring the already-wired dropzones.

The per-format `/formats/<ext>` pages carry an "Analyse any file" CTA (`#fmtPick`)
that opens the OS file picker, stashes the pick in `window._anrPendingFile`, and
SPA-navigates home, where `boot()` analyses it. Browsers without the View
Transitions API fall back to full-page navigation.
